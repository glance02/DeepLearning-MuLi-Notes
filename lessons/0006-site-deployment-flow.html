LESSON 06 / FROM EDIT TO PUBLISH

你改的笔记，
走到了哪一步？

从自己的网站开始，分清保存、推送、拉取、构建和发布。

约 5 分钟对应实战笔记
这一小步的目标遇到“网页没更新”时，先指出它可能停在哪一步。

先追踪一个具体例子

你在本地把“第 3 章笔记”增加一段解释。保存之后，这段话还只在电脑里。提交并推送后，GitHub 有了新版本；每日任务启动后，服务器才拉取它。

保存→commit→push→pull→构建、检查→切换入口

构建把 Markdown 转成网页，并验证引用。检查通过，current 软链接才指向新目录；刷新网页后，才有机会读到新内容。

先读一手资料：Git 官方 git pull 的 DESCRIPTION 与 --ff-only 两段。只关注“从哪里取更新”，其余选项以后再看。

只在本地保存笔记，没有 commit、push。明天服务器正常拉取后，网页会怎样？

源码与网页，分别放在哪里？

repo/ 放源文件；venv/ 放构建用的 Python 环境；releases/ 放生成的网站。Nginx 沿着 current 读取某个发布目录中的文件。

repo/ 里的 Markdown
    ↓ build_site.py
releases/新版/ 里的 HTML
    ↑ current 指向它
    ↑ Nginx 读取它
在当前方案中，Nginx 沿着 current，最终读取哪一类目录？

新版构建时发现资源缺失，程序报错退出。current 应怎样处理？

用自己的话，补完一句

“Git 负责把 ______ 带到服务器；构建脚本负责 ______；current 负责指向 ______。”

先自己说，再展开核对

Git 把提交过的源文件变更带到服务器；构建脚本生成并检查网页；current 指向当前发布版本的目录。可以用自己的表达，只要这三个职责分清楚。
